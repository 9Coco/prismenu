# 思考：应用目录（Kicker）与空菜单排查总结

> 日期：2026-08-08  
> 现象：菜单壳能打开，分类可见，但点「办公 / 编程 / …」后「暂无应用」；日志里 Kicker 已扫到几十个应用。  
> 结果：根因是 **fullRepresentation 拿不到 MenuData**，不是 Kicker 没数据。

---

## 1. 目标架构（最终约定）

| 层级 | 技术 | 说明 |
|------|------|------|
| 应用目录 | `org.kde.plasma.private.kicker` → `RootModel` | 与 Kickoff 同一套（KService / KSycoca / applications.menu） |
| 分类名 | Kickoff 本地化名（办公 / 影音 / 系统…） | 经 `nameToId` 映射成 `Office` / `AudioVideo` 等 id |
| UI 数据中枢 | `MenuData.qml`（`allApps` / `rawCategories` / `catalogEpoch`） | AppsBackend 写入，各布局/页面只读 |
| 弹层传参 | **`root.catalog`**（`property alias catalog: menuData`） | **禁止**在 `fullRepresentation` 里写裸 `menuData:` |
| 兜底指针 | `code/CatalogBridge.js`（`.pragma library`） | Loader 丢绑定时仍能拿到同一份目录 |

**不要做的事：**

- 不要用 Python / GMenu 扫 `.desktop` 当主路径（曾作临时绕路，已废弃）
- 不要在 heredoc 里用 `";".join` 拼 Python（会直接跑不起来）
- 不要为了「刷新」反复 `Loader.source = ""` 再赋值（会拆掉页面绑定）

---

## 2. 症状时间线（从外到内）

1. **UI**：点「所有应用程序」→ 左侧有分类；点「办公」→ 「暂无应用」。
2. **曾出现**：多出一个无文字的网格图标 → `ArcAppsPage` 写死 `model: 7`，只有 6 个分类。
3. **日志矛盾**（关键）：
   ```
   ArcMenu Kicker: 53 apps, 10 cats
   ArcMenu: allApps updated → 53
   ArcMenu wirePage ... catalog= 0
   ArcMenu openCategory Office → 0 apps (catalog 0)
   ```
   → **后端有数据，Apps 页读到的 catalog 始终是 0。**

---

## 3. 走过的弯路（避免再踩）

### 3.1 GMenu / Python 扫描

- 想法：对齐 GNOME ArcMenu（GMenu）。
- 问题：KDE 上依赖重、stdout/heredoc/缓冲不可靠；用户明确要 Kickoff 栈。
- 结论：**目录主路径只用 Kicker。**

### 3.2 Kicker `model.data(Qt.UserRole+N)`

- 想法：在 JS 里用 `data()` 按角色偏移读。
- 问题：角色偏移脆弱；Kickoff 实际用的是 delegate 上的 `model.display` / `model.url` / `model.hasChildren`。
- 现行做法：`Instantiator` 嵌套读 QML 角色 + `modelForRow()`。

### 3.3 临时 Python `scan_desktop_apps.py`

- 原因：上一版 Kicker 采集失败时菜单全空，先保证能看见应用。
- 用户纠正后已删除，**不再作为主方案。**

### 3.4 `MenuData` 配置 `undefined` 赋值

```
Unable to assign [undefined] to bool/int/QString
```

- 写法 `plasmoidConfig ? plasmoidConfig.flipHorizontal : false`：对象存在但键缺失时右边仍是 `undefined`。
- 修复：`cfg` / `cfgBool` / `cfgInt` / `cfgStr`，永不把 `undefined` 赋给 typed 属性。
- 图标尺寸若变成 `NaN`，列表行高度会塌掉，看起来像「没菜单项」。

### 3.5 LayoutHost 疯狂 reload

```
layoutLoader.source = "";
layoutLoader.source = src;  // 每次都销毁重建
```

- `allApps` 一更新就连带 reload → 页面 `menuData` 又变 null → `catalog=0`。
- 修复：**只有 `layoutId` 字符串变化才 `setSource`；目录更新只 `wireItem()`。**

### 3.6 Windows CRLF 导致 `./reload.sh` 失败

```
env: $'bash\r': No such file or directory
```

- hgfs + Windows 编辑器易把 `.sh` 存成 CRLF。
- 仓库已有 `.gitattributes`：`*.sh text eol=lf`。
- VM 内应急：`sed -i 's/\r$//' reload.sh install.sh`

## 4. 真正根因（终于能看见的那一下）

Plasma 里 **`fullRepresentation` / `compactRepresentation` 经常看不到外层 sibling 的 `id`**。

错误写法：

```qml
fullRepresentation: Item {
    LayoutHost {
        menuData: menuData   // 这里的 menuData 经常是 undefined/null！
    }
}
```

正确写法：

```qml
PlasmoidItem {
    id: root
    property alias catalog: menuData   // 显式挂到 root 上

    MenuData { id: menuData ... }

    fullRepresentation: Item {
        LayoutHost {
            menuData: root.catalog     // 必须走 root
        }
    }
}
```

再加：

- `CatalogBridge.setMenuData(menuData)`：全局兜底  
- `catalogEpoch++`：目录更新时强制 UI 刷新  
- `ArcAppsPage.dataHost`：本地 `menuData` 为空时读 Bridge  

日志从 `catalog= 0` 变为能列出应用后，问题即确认。

| 文件 | 职责 |
|------|------|
| `ui/AppsBackend.qml` | Kicker `RootModel` + Instantiator 采集 → `allApps` / `rawCategories` |

## 6. 日常调试流程（给后续 AI / 自己）

### 6.1 重装并打日志（推荐）

```bash
cd /mnt/hgfs/arcMenuOnKde/plasma-arcmenu
chmod +x reload.sh install.sh
./reload.sh
```

日志（Windows/Cursor 可直接读）：

- `plasma-arcmenu/logs/latest-reload.log`
- `plasma-arcmenu/logs/plasmashell-*.log`

点菜单后再抓 journal：

```bash
./reload.sh journal
```

### 6.2 健康日志长什么样

```
ArcMenu catalog registered on bridge
ArcMenu Kicker: 53 apps, 10 cats
ArcMenu: allApps updated → 53 epoch N
ArcMenu LayoutHost wireItem catalog= 53
ArcMenu ArcAppsPage catalog ready: 53
ArcMenu openCategory Office → K apps (catalog 53)
```

角标（菜单右上）：`arcmenu · 53 apps · eN`

### 6.3 若又变成「暂无应用」

按顺序查：

1. 有没有 `Kicker: N apps`？  
   - 没有 → AppsBackend / RootModel / `appletInterface`  
   - 有 → 看下一步
2. `wirePage` / `wireItem` / `openCategory` 的 **catalog=** 是不是 0？  
   - 是 0 → **又丢 MenuData 引用了**（查是否又在 fullRep 里写了裸 `menuData:`，或 LayoutHost 又在狂 reload）
3. `catalog` 非 0 但分类下仍 0 → `nameToId` / `appsInCategory` 类别 id 对不上
4. 脚本报 `bash\r` → CRLF，先 `sed -i 's/\r$//' *.sh`

## 7. Kicker 采集要点（写 AppsBackend 时）

```text
RootModel
  appletInterface: plasmoid
  flat: false
  showAllApps: true          // 便于拿全量；分类仍走各 Group 行
  showRecent*/Power: false
  autoPopulate: false → refresh()

跳过：Favorites / All Applications / Recent / 空名 / ---
识别全量行：description 含 KICKER_ALL_MODEL
分类行：hasChildren + modelForRow(i)
应用行：model.display / url / favoriteId / decoration
```

用 **Instantiator/ListView delegate 角色**，不要猜 `Qt.UserRole + N`。

## 8. 后续改动检查清单

- [ ] 弹层内凡需要目录的，一律 `root.catalog` 或 `CatalogBridge`，不用裸 id  
- [ ] LayoutHost 仅在 `menuLayoutId` 变化时换源  
- [ ] 改完用 `./reload.sh`，看 `openCategory … catalog 53` 而不是 `0`  
- [ ] 新增 `.sh` 保持 LF（`.gitattributes`）  
- [ ] 不把 Python/GMenu 扫盘接回主路径，除非用户明确要求兜底

## 9. Places 侧栏（首页/文档/下载…）打不开

报错示例：`无法读取文件 xdg:Download。`

- **原因**：`xdg:Download` **不是**合法 KIO URL。  
- **正确做法**：`xdg-user-dir DOWNLOAD` 得到真实路径（中文环境常为 `~/下载`），再用 `kioclient exec` / `dolphin` 打开。  
- **实现**：`AppsBackend.openXdgUserDir()`；侧栏项用 `place: "DOWNLOAD"` 等字段，不要写 `exec: "xdg-open xdg:…"`。

---

## 10. 一句话结论

**Kicker 一直是好的；空菜单是因为 Plasma 弹层作用域拿不到 `MenuData`，再被 LayoutHost 反复 reload 放大。**  
修好 `root.catalog` + Bridge + 停止无意义 reload 后，分类下的应用就出来了。  
Places 要用 `xdg-user-dir`，不要用假协议 `xdg:Download`。
